# human-decision-board — 判断待ちを先頭に出すダッシュボード

ダッシュボードが答えるべき問いは 1 つ、「このうちどれが自分を待っているか」。

## ページ構成

- `/` — PR ボード (`src/ui-pr-board-page.mjs`)。トリアージ専用。
- `/dashboard` — 運用の俯瞰 (`src/ui-dashboard-page.mjs`)。登録リポジトリ・
  PR 作成・テストワークフロー・キュー。
- `/settings` — 設定。

トップに置くのは判断待ちだけ。運用パネルと同居させると、開いた瞬間に見える
一画面をリポジトリ表とフォームが占め、この仕様が避けようとしている「判断が
必要な 1 件が埋まる」状態をページ構成の側で作ってしまうため。

## 判定状態 (`src/pr-disposition.mjs`)

| state | 条件 | 表示 |
|---|---|---|
| `needs_human` | 審査済みだがブロッカーがある / `action_required` | 人間の判断が必要 (bad) |
| `failed` | `checkStatus: failed` | 審査が失敗 (bad) |
| `in_review` | `queued` / `running` | 審査中 (warn) |
| `auto_ok` | 審査通過・ブロッカー無し | 自動マージ可 (ok) |
| `merged` | `status: merged` | マージ済み (idle) |
| `closed` | `status: closed` | 取り下げ (idle) |

ブロッカーはマージブロック理由、人間への確認、閾値超過のマージリスク、
必要な動作確認、そしてワーカー失敗時の `error`。すべて右ペインの詳細に文言として出す。
左ペインは対象を素早く選ぶための 3 項目に絞り、詳細では「なぜ止まっているか」が
隠れないようにする。

そのためブロッカーは `auto_ok` だけでなく**審査が確定したすべての PR**
(`queued` / `running` / `merged` / `closed` 以外) で算出する。`needs_human` や `failed` の
カードこそ理由を必要とするので、`test_ok` に限って算出すると理由が空のまま
「人間の判断が必要」とだけ表示されてしまう。

## 並び順とプロジェクトフィルタ

`state` の優先度 → マージリスク降順 → 更新時刻降順。並べ替えはサービス側
(`LocalPrService.listPullRequests`) が行い、クライアントは順序を保つだけ。
判断が必要な 1 件を、緑の 20 件が埋めてしまうのを防ぐのがこの並びの目的。

一覧上部に「判断が必要なものだけ表示」と、複数プロジェクトを選べるフィルタを置く。
プロジェクト未選択は全件、複数選択時は選択したプロジェクトの和集合を表示する。
表示件数・判断待ち件数・Open 件数もこのプロジェクトフィルタを適用した集合を対象にする。
3 秒ごとの更新では、プロジェクトの候補集合が変化したときだけ `select` の option を
再構築する。選択途中の native multiple-select を更新のたびに閉じたり、スクロール位置を
失わせたりしないためである。フィルタから外れた PR は選択も解除し、一覧に無いカードの
詳細が右ペインに残らないようにする。Open な PR が無くなったプロジェクトは選択からも
外す。option を作り直した `select` に選べない選択が残ると、操作で解除できないまま
絞り込みだけが効き続けるため。選択が空になれば未選択と同じく全件へ戻る。

「何を出すか」の規則は DOM に触らない純関数 (`projectsOf` / `keepKnownProjects` /
`sameProjectOptions` / `boardView`) として `src/ui-pr-board-page.mjs` が持ち、
コントローラはそれを DOM へ結ぶだけにする。ブラウザ側スクリプトは文字列で埋め込まれるため、規則を関数として
切り出さないと生成ソースの正規表現でしか検証できず、実行されないコードでもテストが
通ってしまう。

## カード表示

表ではなくカード。同じマークアップが 360px でも読め、デスクトップでは
自動グリッドに広がり、状態バッジが横スクロールなしで見える。

左ペインの 1 枚に載せるものは 3 項目だけに絞る:

- `#番号` と状態バッジ。`needs_human` は「レビュー項目があります」と表示する
- プロジェクト名
- PR タイトル

番号は状態バッジの左上に置く。マージリスク・ブロッカー・テスト・自動マージ結果などの
判断材料は右ペインの詳細に集約する。リストの色と状態で選ぶ対象を把握できるため、数値の
マージリスクを左ペインに重ねて表示しない。

カードは `role="button"` + `tabIndex` + Enter/Space で選択でき、選択すると
詳細に判断・レビュー計画・テスト・レビュー・差分解析・操作が出る。
差分解析は要約 (ゲート・違反・複雑度) だけを出し、Anatomia の生 payload は
出さない。読む人はおらず、解析対象リポジトリのパスや関数名を画面と DOM に
そのまま並べるだけになるため。
テスト詳細では失敗したケースの出力を `details` の折りたたみで出す
(秘匿値はマスク済み、末尾のみ保持した場合はその旨をラベルに出す)。出力を
持たない過去のレコードでは折りたたみ自体を出さない。
すべて `createElement` + `textContent` で組む。値はローカル審査の出力だが、
PR タイトルを HTML 文字列に混ぜればテンプレートインジェクション面になる。

## レスポンシブ

`src/ui-styles.mjs` が正本。デスクトップを先に書き、2 段のブレークポイントで
多カラム構造を畳む。

- `max-width: 960px` — PR ボードの 2 ペイン (左リスト / 右詳細) → 1 カラム。
  リスト側の高さ制限と詳細側の sticky も外し、狭い画面では従来どおり
  カード → 詳細の順で縦に読める。
- `max-width: 700px` — 以下を畳む。
  - カードグリッド → 1 カラム
  - `dl.meta` の `max-content 1fr` → 1 カラム
  - ナビゲーションは全幅・等分
  - 入力とボタンは `font-size: 16px` (iOS Safari のフォーカス時ズーム抑止) と
    `min-height: 44px` (タッチ目標)
  - 表は `.table-scroll` に入れて表だけ横スクロールさせ、`body` は横に
    はみ出させない

スマホで完結させたいのは「人間の判断」なので、判断待ちカード・バッジ・
操作ボタンが幅を優先し、生データや表は縮めて後ろに置く。
