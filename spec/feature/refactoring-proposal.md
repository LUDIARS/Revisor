# プロジェクトのリファクタリング提案

@spec-id SPEC-REFACTORING-PROPOSAL

Rv は複雑度を advisory として報告し、マージ阻害要因にしない。
スコア低下は `advisories` へ記録し、直接のブロック理由にも、自動マージの
リスク加点 (複雑度所見の件数による間接加点を含む) にも使わない。
レビュアーも複雑度だけを理由に修正・動作確認・人間承認を要求しない。

登録プロジェクト一覧と repositories API に `refactoringProposal` を表示する。
同じ repository の、head と reviewedHeadSha が一致する完了レビューのうち、
作成日時が最新の計測済み PR を根拠とする。closed・未完了・head 不一致は除外。
マージ済み PR も対象とし、後続の計測済みレビューが健全ならマークを解除する。
未計測レビューは既存の観測を解除しない。一覧表示では保存済み結果だけを読む。
一覧の記録は解析結果を持たない (SPEC-PR-LIST-SLIM-RECORD) ので、repository ごとに
作成日時の新しい順に解析結果を 1 件ずつ読み、最初の計測済みレビューで打ち切る。
判定は (PR id, updatedAt) で再利用し、記録が変わらない限り解析結果を読み直さない。
これは根拠 PR 時点の観測であり、現在の main 全体の健全性を保証するものではない。

以下のいずれかで「◆ リファクタリング提案 (助言)」を表示する。

- 計測対象関数があり、集計複雑度スコアが 50 以下。
- 計測対象関数があり、関数の最大複雑度 (呼び出し出次数 + 1) が 20 以上。
- プロジェクト全体の孤立関数が 5 件以上。変更の有無で絞り込まない。

関数の最大複雑度は、関数数と件数が一致する版付き `quality.functionComplexity`
スナップショットから求める。集計側の別指標 `maximumCyclomatic` では代用しない。
完全な複雑度スナップショットまたは全体孤立関数の計測が欠けるレビューは、
取得済みの所見だけで提案閾値に達した場合を除き未計測とする。

閾値は `REFACTORING_THRESHOLDS` に集約する。フラグメントはプロジェクト全体の
孤立コードを指す。head の Anatomia 解析時に `review --repo <head worktree> --json`
を追加実行し、切り詰め前の `summary.orphans` を `quality.projectOrphans` に保存する。
既定50件に制限される `orphans` 配列の長さや差分配列では代用しない。PR 間で加算もしない。
ベースライン側はこの全体計測を省略し、最終解析・Anatomia 部分再審査は現在の head で再取得する。
登録プロジェクトのキャッシュを流用せず、対象 worktree と `ANATOMIA_CACHE=off` を指定する。
失敗・欠損・不正な総数は unavailable として記録し、0件へ変換せずマージ判定にも渡さない。
全体計測が未導入の過去レビューは、差分内孤立要素で代用せず未計測と表示する。
孤立関数は静的に呼び出し元が確認できない関数であり、不要コードの断定ではない。
Anatomia 全体 review の対象集合をそのまま使用し、テスト関数などを Rv 独自に除外しない。
根拠 PR 番号、数値、閾値を表示し、未計測と提案なしを区別する。
提案の有無は merge 判定へ渡さない。
